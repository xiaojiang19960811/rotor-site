# 「是管理员」不等于「有管理员权限」

> 栏目：实验日志 ｜ 合集：基础设施 ｜ 来源：wiki/bugs/Windows 低完整性目录导致 NSIS 安装退出（已核验）

结论先行：Windows 上"账号是管理员"和"进程实际拿到管理员权限"是两件事。一个桌面客户端的安装包放在工程目录里双击，选择"为所有用户安装"后向导直接消失：无报错、无 UAC 提示。根因不在账号、不在 UAC，而在文件本身：安装包继承了父目录的低完整性标签，Windows 按"用户完整性"与"文件完整性"取低者启动进程，安装器的提权子进程拿不到所需级别，直接退出。

## 现象：无提示的消失

双击安装包 → 安装向导出现 → 选择"为所有用户安装" → 向导直接消失。没有错误对话框，没有 UAC 提权弹窗，没有日志提示。第一反应通常是：UAC 坏了？安装包坏了？账号权限不够？

逐一排除：账号确实在管理员组；同一个安装包复制到普通下载目录，就能正常弹出 UAC 并继续。文件没坏，账号没问题，问题跟着"目录"走。

## 对照实验：同一文件，换目录就好

对原目录和下载目录的两份安装包做哈希对照：摘要一致，文件本身没有区别。再用同一个诊断程序在两个目录分别读取进程完整性，结果一边是低完整性、提权检查失败，一边是高完整性、提权检查通过。两次诊断里，账号类型读数都是管理员。

账号身份完全相同，进程的实际完整性却一高一低。**"是管理员"描述的是账号，"能不能提权"描述的是进程。**

## 定义：完整性级别是第二道门

Windows 除了 ACL（谁能读写），还有一道强制完整性控制（Mandatory Integrity Control）：完整性级别。创建进程时，系统取"用户令牌完整性"和"可执行文件完整性"两者中的较低者，作为新进程的完整性。

低完整性标签可以通过继承从父目录传下来：目录被标了低完整性，里面落下的文件跟着变低。安装包从构建流程落到工程目录，顺手继承了低标签。此后无论什么账号双击它，进程完整性都先被文件这一头按住。

NSIS 的"为所有用户安装"要走提权子进程。子进程要往系统级目录写文件，需要的完整性拿不到，就以退出码 0x666666 直接退出，外层向导跟着消失。连 UAC 弹窗的机会都没有：弹窗只在"能提权"时出现，"根本不够格提权"时直接出局。

## 排障顺序：先看文件，再看账号

这次复盘沉淀下来的顺序：

1. **先看退出码**：安装器消失不是"没反应"，NSIS 给了 0x666666。有退出码就有方向。
2. **查文件的强制标签**：用 `icacls <安装包>` 看有没有 Low Mandatory Level；有就逐级往上查父目录，找到标签的源头。
3. **读实际完整性，不读账号名**：用诊断手段读进程的实际完整性级别。账号在管理员组、右键"以管理员身份运行"，都不能代替这一次读取。
4. **隔离变量**：复制到无低完整性继承的普通目录再启动，确认"换目录就好"，把"文件坏了"彻底排除。

以及三条"不要"：不要据此去改账户配置，不要关 UAC，不要批量重置工程目录的 ACL。标签的源头（哪个工具、何时设置的）还没核实，动手改 ACL 是在修一个没确诊的病。

## 收束

下次安装器无提示闪退，别先怀疑账号和 UAC：先问文件是从哪个目录来的，再用 icacls 看它继承了什么。
