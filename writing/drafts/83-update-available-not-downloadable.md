# 显示有新版，不等于能下载到新版

> 栏目：实验日志 ｜ 合集：AI 基础设施 ｜ 来源：wiki/bugs/2026-10-19 桌面客户端更新源未部署与假绿灯（已脱敏） ｜ 状态：已写稿·即将发布

结论先说：设置里显示"有新版"，不等于新版真的能下载。一次更新提示故障里，三层各自合理的设计合起来，把故障藏了起来：生产环境根本没有部署更新清单，兜底逻辑把缺失的清单当成网页返回；本机联调的 Mock 顶替了生产地址，用一个假版本号撑起了"有新版"的显示；配置备份放错了目录，让配置检查的告警也被淹没。修完之后，验证的标准变了：不再看界面显示什么，而看三条产物证据：清单是不是真正的 JSON、安装包长度对不对、不存在的文件是不是真的返回 404。

## 现象：有新版的提示，下载不到东西

用户反馈设置里一直没有新版本。排查期间那一行一度显示"新版 0.2.2"，但点"下载新版"只会打开网关首页，下载不到任何安装包。真实用户侧始终停留在"暂时无法连接"或"已是最新版本"，既看不到新版，也不会报错。

影响范围是全部外部客户端：更新提示形同虚设，而界面不暴露失败原因，运维与用户都容易误判为网络问题。

## 三层根因：各自合理，合起来藏住了故障

1. **生产没有更新清单**：更新清单、安装包这些路径，全部落到网关嵌入前端的单页应用兜底：一律返回 200 和网页。更新检查模块把网页当 JSON 解析失败，按设计静默降级为"不可用"。离线时不打扰是对的，但这里它把"服务端没部署"也当成了"暂时连不上"。
2. **本机 Mock 顶替了生产地址**：本机联调配置把更新地址覆盖为本地 Mock 服务，Mock 返回版本号 0.2.2、校验值全是 0、下载地址指向一个目录。界面因此显示"新版"，但下载必然失败。这是假绿灯：它掩盖了第一层，也让"设置里明明有新版"一度成为争议点。
3. **配置备份放错了位置**：站点配置的备份文件放在了配置目录里，配置加载会把备份一起读进去。配置检查报了 8 条同名冲突告警，最终生效的配置取决于文件名的字典序。

三层里没有一层是"写错了代码"：兜底返回网页是单页应用的正常行为，静默降级是更新模块的既定设计，Mock 是联调的常用手段，备份放配置目录是随手的操作。故障不在某一层，而在三层叠加之后：每一层都把上一层的失败消化掉了，到界面只剩一句看似正常的"有新版"。

## 修复：四处改动，一个新标准

1. 服务端加两条精确路由：清单精确匹配，返回 JSON 且不缓存；安装包目录前缀匹配，长缓存、保留断点续传。
2. 生成带真实校验值的清单，连同安装包一起部署到更新源目录。
3. 配置备份移出配置目录，配置检查恢复无告警后再重载。
4. 本机更新地址切回生产地址，联调 Mock 停止。

前三处是补部署缺口，第四处是拆掉假绿灯。但真正换掉的是验证标准：以后更新通道的验收，不再以"界面显示新版"为准，而以三条产物证据为准。

## 验证与边界

发布后从公网验证了五条：

1. 清单请求返回 200、JSON 类型、不缓存，版本号是当次发布的版本。
2. 安装包 HEAD 请求返回 200、长度与清单一致、长缓存；分段请求返回 206。
3. 不存在的文件名返回 404：如果返回 200 加网页，说明又被单页兜底了。
4. 从公网完整下载约 290 MB 的安装包，耗时约 24 秒，复算校验值与清单一致；首页仍正常返回，后端未受影响。
5. 本机检查返回"有新版"，且把 Mock 临时改成一个不存在的探测版本后仍返回生产版本，证明检查已不再读 Mock。

三条防复发措施值得记：发布后必须从公网验证清单、安装包、404 这三条，只在本机连 Mock 验证等于没验证；联调 Mock 必须使用与生产明显不同的版本号或标记，避免"看起来更新成功"的假绿灯；配置备份一律放在配置目录之外。

还有一个边界要说清楚：静默降级本身是合理的，离线时不该用报错打扰用户。但排障时需要一条能区分"网络不通"与"清单是网页"的证据，优先看响应头而非界面文案。界面文案是给用户看的，不是给排障用的。

一句话收束：界面显示"有新版"只是更新链路的最后一环在说话；清单、安装包、404 这三条产物证据，才是更新真的可用的证明。
